# ADR-005: Deployment & CI/CD – Docker + GitHub Actions, AWS Production

**Status:** Accepted  
**Date:** 2026-05-18  
**Deciders:** Emmanuel Adoum (Tech Lead), Chidima Praise

---

## Context

We need a reproducible, scalable deployment pipeline from day one.  
The platform includes backend (FastAPI + Celery), frontend (Next.js), mobile builds (Expo), and databases (PostgreSQL, Redis).

Options:  
- Container orchestration: Docker Compose (dev), Kubernetes (prod).  
- CI/CD: GitHub Actions, GitLab CI, Jenkins.  
- Cloud: AWS, GCP, Azure, or self‑hosted.

---

## Decision

- **Containerisation:** Docker + Docker Compose for development and staging.  
- **Orchestration:** For production, start with single‑host Docker Compose on AWS EC2; scale later to ECS/EKS if needed.
- **CI/CD:** GitHub Actions (build, test, push to Docker Hub, deploy).  
- **Production cloud:** AWS (EC2, RDS, ElastiCache, S3, CloudFront).

---

## Rationale

- **Docker** ensures identical environments from laptop to production.
- **GitHub Actions** integrated with repo, free for public/private, supports matrix builds (Python 3.11, Node 18, Expo).
- **AWS** chosen because MTN Ghana uses AWS for internal tools; RDS and ElastiCache reduce operational burden.
- **Single‑host Docker Compose** keeps initial complexity low; we can migrate to ECS when needed.

---

## Consequences

- **Positive:** Fast onboarding, one‑command `docker-compose up`.  
  GitHub Actions automates testing and deployment on every push to `main`.
- **Negative:** Single‑host is not highly available; acceptable for Phase 1.  
  Must add health checks and auto‑restart policies.

---

## Alternatives Considered

- **Kubernetes (EKS)** – Too complex for phase 1, overkill for 1,000 concurrent users.
- **Heroku** – Easier but vendor lock‑in, expensive at scale, no Redis task broker out of the box.
- **GitLab CI** – Similar to GitHub Actions, but team already uses GitHub.

---

## Deployment Workflow (CI/CD)

1. Push to `main` → GitHub Actions.
2. Run backend tests (pytest), frontend lint, mobile type check.
3. Build Docker images (`backend`, `frontend`).
4. Push images to Docker Hub.
5. SSH into EC2, pull images, run `docker-compose down && up -d`.
6. Run database migrations (Alembic automatically on startup).

---

## Compliance

-  Reproducible builds – Docker.
-  CI/CD – GitHub Actions.
-  Production‑ready cloud – AWS with SSL (Let's Encrypt).
